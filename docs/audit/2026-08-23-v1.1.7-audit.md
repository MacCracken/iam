## TL;DR

**Not a pass on arrival. Five findings, one of them a live
contract violation; all five fixed and regression-tested in this
cut.** Post-fix the tree is clean on every gate.

The headline: **iam could silently emit five lines instead of six.**
ADR 0002 guarantees six required labels always appear, and CI gates
on it — but a sufficiently long probe value overflowed the 4 KiB
output buffer, and because the driver only advances its cursor on a
positive renderer return, the *entire* `CPU:` line disappeared rather
than the value truncating. Reproduced, fixed, and locked with a test
that fails against the v1.1.6 source.

| ID | Severity | Finding | Status |
|---|---|---|---|
| F-003 | **HIGH** | Unbounded value column drops a *required* line on overflow — breaks ADR 0002's six-line guarantee | **Fixed** |
| F-004 | MEDIUM | Report flushed with a single unchecked `write(2)`; short write truncates, `-EINTR` loses output | **Fixed** |
| F-005 | LOW | Value sanitizer missed DEL (0x7F), which is part of C0 by ECMA-48 | **Fixed** |
| F-006 | LOW | `iam_append` was dead code — defined, never called | **Fixed** |
| F-007 | LOW | Copy primitives used an overflow-prone additive bound and accepted a negative length, silently rewinding the write cursor | **Fixed** |
| F-002 | INFO | `strlen` on mihi cstrings is trust-dependent | **Carries** (see §C) |
| F-001 | — | TTY-escape sanitization | Closed at v0.9.0; **extended** by F-005 |

Assertions **122 → 141**. Runtime output on archaemenid is
byte-identical to v1.1.6 — every fix changes behaviour only for
inputs that were already pathological.

## Section A — Findings

### F-003 — Unbounded value column drops a required line (HIGH, fixed)

**The defect.** `src/main.cyr` hands mihi scratch buffers far larger
than any line can be: 8192 bytes for the CPU model, 4096 for the
memory probe, 1024 for the distro string. The output buffer is 4096
bytes total for all seven lines. Nothing bounded a single value
against the buffer it had to fit into, so `iam_render` returned its
overflow sentinel — and the driver's accumulate step is:

```
n = iam_render(&out + pos, IAM_OUT_CAP - pos, "CPU", cpu);
if (n > 0) { pos = pos + n; }
```

On overflow `n` is negative, `pos` does not advance, and **the line
is skipped entirely**. The next line renders normally. The result is
a report that is missing a required label, with no error anywhere.

**Why four previous audits missed it — and the uncomfortable part.**
`SECURITY.md` has named this exact threat since the first audit:

> **mihi return-data abuse** — if mihi returns adversarially-**large**
> or malformed buffers […] iam's display formatter must still bound
> writes.

So this was not an unimagined threat. It was a documented one that
nothing verified. What the audits actually checked was the literal
sentence — *"bound writes"* — and writes **were** bounded the whole
time: `iam_copy`'s capacity check never let a byte past the end of the
buffer, and no overflow ever occurred. The unchecked half was what
happens *after* the bound is hit. Every audit confirmed iam does not
overflow; none asked what iam prints when it declines to.

F-002's framing compounded it. Carrying "iam trusts mihi's NUL
invariant" as the standing INFO item anchored each subsequent review on
*malformed* input, when F-003 needs nothing malformed at all — a
correctly NUL-terminated 5000-byte string is enough.

**Reproduced**, with a 5000-byte CPU model against the v1.1.6 source:

```
Distro: Arch Linux
Host:   archaemenid
Kernel: Linux 7.1.8-arch1-3
Uptime: 1d 1h
Memory: 59 GiB
--- line count: 5
```

`CPU:` is gone. This fails ADR 0002's contract and would fail the CI
smoke gate (`expected 6 or 7 output lines, got 5`).

**Reachability.** Not remote, and not unprivileged — the sources are
`/proc/cpuinfo`, `/etc/os-release`, and the accelerator device name.
It needs someone able to influence one of those: a crafted container
image with a doctored `/etc/os-release` (`PRETTY_NAME` is a free-text
field iam reads through a 1 KiB buffer), a doctored `/proc` mount, or
root on the box. That is a real configuration, not a theoretical one,
and the failure is silent — which is what earns it HIGH rather than
MEDIUM. It is a correctness and contract failure, not a memory-safety
one: `iam_copy`'s capacity check was doing its job throughout, and no
overflow ever occurred.

**Fix.** `IAM_VALUE_MAX = 256`, enforced inside `iam_copy_value` —
the single choke point all four renderers route their value column
through. An over-long value now truncates and the line always
renders. 256 is ~5x the longest value seen in practice (a
`/proc/cpuinfo` model name runs ~50 bytes, a `PRETTY_NAME` ~40, and
POSIX caps a hostname at 255). Worst-case seven-line output with
every value clamped is **1673 bytes**, comfortably inside the 4 KiB
buffer:

| Line | Worst case |
|---|---:|
| Distro / Host / CPU | 8 + 256 + 1 = 265 each |
| Kernel (two values + separator) | 8 + 256 + 1 + 256 + 1 = 522 |
| GPU (name + bracketed size) | 8 + 256 + 1 + 1 + 24 + 1 + 1 = 292 |
| Uptime / Memory (formatter output, ≤24) | 32 each |
| **Total** | **1673** |

Growing `IAM_OUT_CAP` was considered and rejected: it does not
actually fix the class (the CPU scratch is 8 KiB, so a value can
exceed any fixed output cap), and a 16 KiB stack buffer would blow the
~12 KiB agnos user-stack budget that v1.1.5 was specifically cut to
respect.

**Truncation lands on a character boundary.** Cutting at a fixed byte
offset can slice a UTF-8 sequence in half and emit an invalid
fragment, so the clamp backs off while the byte at the cut is a
continuation byte (0x80–0xBF). `load8` was verified unsigned before
relying on that range test.

### F-004 — Unchecked single write (MEDIUM, fixed)

The report was flushed with `print(&out, pos)`. Following it down:

```
fn print(msg, len): i64 { file_write(STDOUT, msg, len); return 0; }
fn file_write(fd, buf, len): i64 { return sys_write(fd, buf, len); }
fn sys_write(fd, buf, count): i64 { return syscall(SYS_WRITE, fd, buf, count); }
```

A bare `write(2)` whose return value is **discarded at two levels**.
`write` is under no obligation to consume the whole buffer, so a short
write silently truncates the report and an `-EINTR` loses it outright.
This is the exact symmetric counterpart of the short-read defect mihi's
own 1.2.3 audit filed as A-1 and fixed — and it lands on the login
path, where a half-printed MOTD is a visible failure.

**Fix.** `iam_flush` loops until the kernel has taken every byte,
retrying `-EINTR` and stopping on any other negative return (EPIPE,
EIO — there is nowhere useful to report it, and ADR 0001 §6 keeps the
exit code at 0 regardless). `n == 0` also stops the loop rather than
spinning.

**Portability note worth recording**: the fix first used the stdlib's
`EINTR` constant, which compiles on host and `--aarch64` and **fails
the `--agnos` build** — `EINTR` is declared in the Linux and macOS
syscall modules but not in `syscalls_x86_64_agnos.cyr`. iam is an agnos
build target, so the constant is now defined locally as `IAM_EINTR`.
The cross-target build gate caught this; a host-only CI would not have.

**Verified not to hang** — the risk any retry loop introduces.
Early-closed pipe (`iam | head -c 10`) and fully closed stdout both
exit 0 immediately with no spin.

### F-005 — DEL (0x7F) not sanitized (LOW, fixed)

The F-001 sanitizer replaces any value byte `< 0x20`. By ECMA-48 the
C0 control set is **0x00–0x1F plus DEL (0x7F)**, so DEL passed through
a filter whose stated intent is "no control bytes in the value column."
Low impact — DEL is not an escape introducer — but it is a gap between
the sanitizer's documented intent and its behaviour.

**Fix.** `if (b < 32 || b == 127)`.

**C1 (0x80–0x9F) is deliberately still unfiltered**, and this is the
more interesting half. General guidance on terminal sanitization
recommends stripping C0, DEL, *and* C1. That guidance is wrong for
this program: on a UTF-8 terminal, bytes 0x80–0x9F only ever occur as
multibyte continuation bytes, never as standalone C1 controls.
Filtering them would corrupt every legitimate non-ASCII value — a
distro name with an accented character — while protecting against
nothing a UTF-8 terminal would have interpreted. Recorded here so a
future audit does not "fix" it.

### F-006 — Dead code (LOW, fixed)

`iam_append` was defined in `src/main.cyr` and never called; the driver
inlines `if (n > 0) { pos = pos + n; }` at each site. Dead code in a
150-line file whose stated value is being small and auditable. Its
slot is now `iam_flush` (F-004).

### F-007 — Copy-primitive bounds (LOW, fixed)

`iam_copy` and `iam_copy_value` guarded with `if (pos + len > cap)`.
Two problems, both defence-in-depth rather than live bugs:

1. **Additive form can wrap.** A hostile `len` makes `pos + len`
   overflow to a negative value that passes the check. Not reachable
   today (`len` comes from `strlen` on real memory), but the
   subtractive form `len > cap - pos` cannot wrap for the non-negative
   `pos`/`cap` this file maintains, and costs nothing.
2. **Negative `len` was accepted and silently rewound the cursor.**
   With `len = -1` the check passes, the copy loop does not execute,
   and the function returns `pos + len` — i.e. `pos - 1`. The write
   cursor moves *backwards* and the next write overwrites a byte of
   the previous line.

The second is worth dwelling on because of how it nearly escaped: the
first version of the regression test called `iam_copy(buf, 1024, 0,
"abc", -1)` and **passed against the unfixed source**, because at
`pos == 0` the buggy return `0 + (-1)` is `-1` — the correct answer by
coincidence. Only with the cursor advanced does the defect show:
against v1.1.6, `iam_copy(buf, 1024, 10, "abc", -1)` returns **9**.
The test now uses a non-zero `pos` and fails against v1.1.6 as it must.

## Section C — Carry-forward

### F-002 — `strlen` on mihi cstrings is trust-dependent (INFO, carries)

Unchanged in mechanism: `iam_render` calls `strlen(value)` on a
mihi-returned pointer, so a probe that returned a non-NUL-terminated
buffer would walk past its end. mihi's API has been frozen since 1.0.0
and its 1.2.3 audit hardened the read path that produces these strings,
so the invariant is better-supported than when F-002 was filed.

**Its residual risk is now smaller in one specific way**: F-003's clamp
bounds how much of an over-long value is ever *copied* (256 bytes).
It does **not** bound the `strlen` scan itself, which still runs to the
first NUL. Closing F-002 properly needs a bounded length from mihi —
an `n`-limited probe variant — which is a mihi API question, not an iam
one. Keep as INFO.

### Syscall surface

iam's own `src/` issues exactly one direct syscall: `syscall(SYS_EXIT, r)`.
Everything else routes through mihi probes and the stdout flush. Re-confirmed
this cut: no `exec`/`fork`/`clone`, no sockets, no `dlopen`, no `getenv`, no
direct `/proc` `/sys` `/etc` opens, no stack buffer ≥ 64 KiB. The CI security
scan enforces all of these.

## Section D — Documentation audit

- **ADR 0002's six-required-lines guarantee was, strictly, not true**
  before this cut — F-003 made it violable. The ADR text needed no
  change; the code needed to start honouring it. Noted here because the
  ADR is the v1.0 contract and "the doc was right, the code was wrong"
  is the outcome worth recording.
- **ADR 0001 §5 / §6 re-verified** against behaviour: TTY == pipe holds
  byte-for-byte, and exit stays 0 including on the EPIPE path.
- **Formatting normalized.** `src/main.cyr` and `tests/iam.tcyr` carried
  continuation lines using aligned-to-open-paren indentation where
  canonical style is 2 spaces per open paren — a divergence 6.5.35's
  formatter flags and 6.2.37's accepted. Now canonical, closing the last
  cleanliness gap. Whitespace-only: `diff -w` is empty for both files,
  `cyrius fmt` is idempotent on the result, and 141/0 passes before and
  after. This had been deferred twice on readability grounds; the
  ecosystem precedent (mihi normalized its own test file at 1.2.2)
  settles it.

## Next audit trigger

- Any mihi major bump, or any mihi cut that changes probe return shape
  or the size of the scratch a probe is given — F-003's constant is
  sized against today's buffers.
- Any change to `IAM_OUT_CAP`, `IAM_VALUE_MAX`, or the renderer set.
- Before v2.0, if colour is reconsidered (ADR 0001 §5): a colour path
  reintroduces escape bytes iam currently guarantees absent, and F-001 /
  F-005 would need re-argument from scratch.
